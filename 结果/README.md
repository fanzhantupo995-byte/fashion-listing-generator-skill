# 结果目录管理规则

## 一条铁律

**一个商品 = 一个项目文件夹。任何图都不许直接丢在 `结果/` 根目录下。**

## 项目文件夹命名

```
日期_品类_商品简称
2026-11-02_女装-黑色针织连衣裙
2026-11-03_男装-加厚卫衣
```

- 日期：`YYYY-MM-DD`，用开工当天
- 品类：自由填写（女装 / 男装 / 童装 / 内衣 / 家居服 / 鞋包……不限），与 `参考模板/` 下的品类目录对应
- 商品简称：2~8 字，不带空格和斜杠
- 项目文件夹名作为稳定的项目标识，后续跨日修改也不改名。方案迭代只增加方案版本，不另建或重命名项目文件夹。

## 项目文件夹内部

```
2026-11-02_女装_针织连衣裙/
├── 商品信息.md      # 品名、SKU、颜色款式、尺码、平台，开工前填
├── 2026-11-02_女装_针织连衣裙_方案_v001.md
├── 2026-11-02_女装_针织连衣裙_方案_v001.html
├── 01-素材/         # 用户给的原图、参考图，只读不改
├── 02-生成/         # 生成的单页图，按页码命名
└── 03-成品/         # 拼好的长图、裁切好的交付图
```

## 方案文件命名与版本

- 正式文件名为 `<项目标识>_方案_vNNN.md` 和同名 `.html`，从 `v001` 起递增；项目标识使用项目文件夹名。模板仍保留 `结果/_项目模板/方案.md`，复制到项目时才按规则命名。
- 文件名不得使用空格、路径分隔符或 `<>:"|?*` 等字符；同名项目冲突时，在首次创建项目时加稳定的款号或序号，不在每次修订时换标识。
- Markdown 与 HTML 必须同一项目、同一版本、同一内容，页面标题也标明项目与版本。正式项目内不用裸名 `方案.md`、`方案.html`，不用“最终版”“最新版”“修改版2”等模糊名称。
- 创建前检查现有版本及商品信息中的登记，使用最大已占用版本号加一，不覆盖已有文件；若同版本只缺 HTML，则由该版本 Markdown 补齐，不另造不同内容的同号文件。
- 尚未展示的当前草稿可在原版本内编辑；一旦展示给用户，任何任务、素材、提示词或其他方案内容修改均生成下一版本，旧版本原样保留。仅记录用户确认状态和原话可更新对应版本的确认记录，Markdown 与 HTML 同步。
- 所有版本的成对文件保留在项目根目录，历史版本通过登记标为已替代或被否决，不搬动或删除，以免相对素材路径和旧预览链接失效。HTML 图片路径相对项目根目录，不使用当前机器的绝对路径。
- `商品信息.md` 维护方案版本登记：文件路径、创建时间、修改摘要、关联基准图及提示词版本、状态、确认时间与用户原话；分别标明“当前待确认版本”和“当前已确认执行版本”。编号最大不等于已确认。
- 新版确认前不自动切换执行版本；若新版变更了商品细节、基准或任务要求，受影响任务暂停，不能继续按已失效的旧内容生成。用户确认具体版本和范围后再更新执行指向。
- 打开预览、交付方案和开始正式生成前，核对登记中的文件对、版本及确认范围。基准图全部确认可用前不创建任何方案版本或预览。

`01-素材/` 内按 SKU 再分子目录，图与 SKU 一一对应，不混放。

基准图准备阶段只建立商品信息、素材和基准图记录，不提前复制整个项目模板或创建方案文件。用户确认所需产品细节基准图全部可用后，才复制 `方案.md` 模板并编写方案及后续提示词。

`02-生成/` 内命名：`01-首屏.jpg`、`02-面料卖点.jpg`…… 页码即顺序，禁止 `未命名-1.png` 这类名字。

## 目录本身不存垃圾

- 方案不放在 `02-生成/`；历史方案按上述版本规则留在项目根目录，登记状态而不覆盖。
- `_项目模板/` 只读，按阶段复制需要的文件，不要在里面直接干活；方案模板须等基准图确认可用后才复制。

## 当前状态

- 本仓库不收录具体商品项目，项目数由使用者在本地维护。
